RNDIS-NAT-Manager

Раздача интернета для кассовых аппаратов по RNDIS (USB), которая не отваливается после перезагрузки хоста — в отличие от штатного общего доступа Windows.

Выбор: _
Почему это вообще нужно

Общий доступ Windows врёт о своём состоянии

Классический ICS хранит статус общего доступа ненадёжно: после перезагрузки, засыпания USB-контроллера или быстрого запуска (Fast Startup) раздача фактически отключается — а чекбокс в свойствах адаптера остаётся визуально включённым. Касса теряет интернет, и это не всегда заметно с первого взгляда.

Было

  • Чекбокс «Разрешить общий доступ» включён визуально
  • Реальная раздача не работает после ребута
  • Fast Startup не даёт USB-стеку переинициализироваться
  • USB selective suspend усыпляет RNDIS-адаптер
  • Никакого способа понять, работает раздача или нет, кроме похода к кассе

Стало

  • WinNAT (New-NetNat) — NAT уровня ядра, не зависит от службы ICS
  • Автозапуск от SYSTEM поднимает раздачу при каждой загрузке
  • Разовый харденинг устраняет Fast Startup / USB suspend / питание адаптера
  • Понятный вердикт в статусе: работает / не переживёт перезагрузку / есть проблема
  • Подробный лог с трассировкой — видно, на каком именно вызове что-то встало
Два механизма, один переключатель

WinNAT или классический ICS — по кнопке [M]

На части машин (например, Windows 10 IoT Enterprise LTSC) компонент WinNAT физически отсутствует в образе. Программа умеет работать через оба механизма и не путает их между собой.

WinNAT — по умолчанию

NAT на уровне ядра через New-NetNat. Не зависит от службы SharedAccess. DHCP/DNS не раздаёт — на кассе прописывается статический IP.

Классический ICS — резерв

Через HNetCfg.HNetShare, включается вручную один раз через саму Windows. Поднимает собственный DHCP — на кассе можно оставить автоматическое получение IP.

Установка

  1. Скачать RNDIS-NAT-Manager.exe из последнего релиза — собирается автоматически в CI при каждом теге.
  2. Запустить от имени администратора — программа сама запросит повышение прав.
  3. [H] — устранить типовые причины отвалов, затем [1] — включить раздачу, затем [6] — поставить автозапуск.
  4. [D] — убедиться, что всё исправно.
  5. Перезагрузить хост целиком и проверить, что статус остался зелёным сам по себе — это единственное реальное доказательство, что раздача переживает перезагрузку.
