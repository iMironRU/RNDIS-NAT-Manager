Менеджер раздачи интернета (NAT) для кассовых аппаратов (ККМ), подключённых к хосту по RNDIS (USB). Решает основную проблему классического ICS: общий доступ к интернету слетает после перезагрузки хоста, даже если чекбокс «Разрешить общий доступ» в свойствах адаптера визуально остаётся включённым.

## Проблема

Windows ICS (Internet Connection Sharing) хранит своё состояние ненадёжно. После перезагрузки, засыпания USB-контроллера или быстрого запуска (Fast Startup) общий доступ фактически отключается — но чекбокс в свойствах адаптера остаётся визуально включённым, интерфейс просто не отражает реальное состояние. В результате касса теряет интернет, и это не всегда заметно на первый взгляд.

## Решение

Скрипт использует **WinNAT** (`New-NetNat`) вместо классического ICS — это NAT на уровне ядра Windows, не зависящий от службы `SharedAccess` и её состояния. Дополнительно скрипт умеет находить и устранять типовые причины отвала самого RNDIS-адаптера:

- **Fast Startup (HiberbootEnabled)** — при гибридном выключении USB-стек не переинициализируется как следует;
- **USB selective suspend** — Windows усыпляет RNDIS-адаптер для экономии энергии;
- **Управление питанием адаптера** — опция «Разрешить отключение устройства для экономии энергии»;
- **PnPCapabilities=24** в реестре — точечный запрет на программное усыпление именно этого USB-устройства;
- автозапуск NAT при загрузке системы через задачу планировщика от имени `SYSTEM` (не зависит от интерактивного входа пользователя и UAC).

На некоторых машинах `New-NetNat`/`Get-NetNat` падают с ошибкой «Недопустимый класс» / `Invalid class`. Проверено вживую: на **Windows 10 IoT Enterprise LTSC 2024** (build 26100) класс `MSFT_NetNat` отсутствует не только в WMI (`Get-CimClass -Namespace root/StandardCimv2 -ClassName MSFT_NetNat` → `WBEM_E_NOT_FOUND`), но и во всех `.mof`-файлах на диске — компонент физически не входит в этот образ Windows (IoT/LTSC-сборки урезаны, раздача интернета не входит в их сценарий использования). Это **не поломка**: `sfc`, `DISM`, `mofcomp`, `winmgmt /resetrepository` — ничего из этого не восстановит отсутствующий компонент, WMI-репозиторий при этом может быть абсолютно здоров (в этом случае было 367 классов в namespace). Для такого случая в программе есть **режим ICS** — классический `HNetCfg.HNetShare`, не зависящий от WinNAT вообще.

## Режим: WinNAT или ICS

Пункт `[M]` переключает активный механизм раздачи. Выбранный режим сохраняется в конфиге и определяет:
- что считает статус/вердикт «работает / не работает»;
- что поднимает автозапуск `[6]` и харденинг `[H]` при повторном запуске;
- какие пункты меню подсвечены как «основные» (пункты другого режима не удаляются — ими можно пользоваться вручную для сравнения/отладки, но одновременно оба механизма включать не стоит: они конкурируют за один адаптер).

**WinNAT** (по умолчанию) — раздача через `New-NetNat`, пункты `[1]`/`[2]`/`[3]`/`[H]`. ККМ настраивается статикой (см. ниже).

**Классический ICS** — раздача через `HNetCfg.HNetShare`, пункт `[8]`. Включается **вручную через саму Windows** (программа только сбрасывает уже включённый ICS, не создаёт его с нуля — это и есть механизм починки «завис»):

1. `Win+R` → `ncpa.cpl` → Enter
2. ПКМ на адаптере, через который у хоста есть интернет (не RNDIS!) → Свойства → вкладка «Доступ»
3. Включить «Разрешить другим пользователям сети использовать подключение к Интернету данного компьютера»
4. В «Подключение домашней сети» выбрать RNDIS-адаптер
5. ОК

После этого Windows сама поднимет на RNDIS-адаптере `192.168.137.1` и свой DHCP — на ККМ можно ставить **DHCP вместо статики**. Переключите режим на ICS (`[M]`), поставьте автозапуск `[6]` — при зависании после перезагрузки автозапуск/`[8]` сбросит его тем же способом, каким чинили вручную классический ICS изначально.

## Меню

`RNDIS-NAT-Manager.exe` запускается с автоповышением прав (нужны права администратора):

| Пункт | Действие |
|---|---|
| 1 | Включить раздачу (WinNAT) |
| 2 | Выключить раздачу (WinNAT) |
| 3 | Пересоздать NAT (сброс, WinNAT) |
| 4 | Ping ККМ |
| 5 | Выбрать сетевой адаптер вручную |
| 6 / 7 | Установить / убрать автозапуск при загрузке (поднимает механизм активного режима) |
| 8 | Сбросить / включить классический ICS |
| 9 | Показать лог |
| D | Диагностика — проверка всех типовых причин отвалов, с учётом активного режима |
| H | Устранить причины отвалов автоматически (разово), в конце поднимает раздачу активным режимом |
| V | Подробный TRACE-лог живьём в консоли (вкл/выкл) |
| M | Переключить режим WinNAT ⇄ ICS |
| C | Настройки |

Все параметры (режим, IP хоста, префикс подсети, IP ККМ, паттерн адаптера, имя NAT) сохраняются в `C:\ProgramData\RNDIS-NAT-Manager\config.json` — исходный код менять не нужно. Лог действий — `C:\ProgramData\RNDIS-NAT-Manager\RNDIS-NAT.log`.

## Настройка на кассе (ККМ)

**Режим WinNAT** — DHCP/DNS не раздаётся, IP прописывается статикой:

- **IP**: из подсети хоста, например `192.168.137.100`
- **Маска**: `255.255.255.0`
- **Шлюз**: IP хоста, по умолчанию `192.168.137.1`
- **DNS**: `1.1.1.1` / `8.8.8.8`

**Режим ICS** — Windows поднимает свой DHCP на RNDIS-адаптере, на кассе достаточно **DHCP** (автоматическое получение IP).

## Установка

1. Скачать `RNDIS-NAT-Manager.exe` из [Releases](../../releases) (собирается автоматически в CI, см. ниже).
2. Запустить от имени администратора.
3. `[H]` — устранить типовые причины отвалов (Fast Startup, USB suspend и т.д.), затем `[1]` — включить раздачу, затем `[6]` — поставить автозапуск.
4. `[D]` — убедиться, что всё исправно.

После `[H]` часть настроек (Fast Startup, USB suspend) вступает в силу только после перезагрузки хоста.

## Сборка из исходников

```powershell
Install-Module ps2exe
Invoke-ps2exe .\RNDIS-NAT-Manager.ps1 .\RNDIS-NAT-Manager.exe -requireAdmin -title "RNDIS NAT Manager"
```

Собирать **без** `-noConsole` — интерактивному меню нужна консоль.

### Автосборка в CI

При пуше в `main` GitHub Actions собирает `.exe` и публикует его как build-артефакт workflow-запуска. При пуше тега вида `v1.0.0` дополнительно создаётся GitHub Release с приложенным `.exe`:

```bash
git tag v1.0.0
git push origin v1.0.0
```

## Требования

- Windows 10/11 или Server с поддержкой WinNAT — **кроме** некоторых IoT/LTSC-сборок, см. выше; на них используйте режим ICS
- Права администратора
- RNDIS-адаптер, определяемый Windows (драйвер ККМ должен быть установлен)
